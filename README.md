# Хронбург — дело о пропавшем Новом годе 🎄

Интерактивный математический адвент-квест: одна история для **ОГЭ** и **ЕГЭ (профиль)**, с раздельными задачами и прогрессом.

## Прототип 0.3

- Главная карта из `assets/maps/chronburg_map_base.png`
- Календарь на 24 дня (пока реализован только день 1)
- Переключение ОГЭ/ЕГЭ профиль
- День 1: «Огонёк надежды», по 4 проверенных математических задания в каждом режиме: 3 контура + завершающий замок Искры времени
- Интерактивный распределительный щит поверх локации, три независимые секции освещения, смена настоящих изображений по мере ремонта
- Задания в модальном окне, математические подсказки и решения в KaTeX
- Сюжетные реплики Тика по мере восстановления света, сцена вручения фонарика
- Необязательные звуковые сигналы (изначально отключены), адаптивная мобильная раскладка
- Резервные аналоги для всех четырёх заданий первого дня (по кнопке после ошибки), подсказки, поле для ответа, математическая клавиатура, черновик для стилуса и мыши
- Первая искра, игрушка-фонарик, простая ёлка и локальное сохранение прогресса
- Экспорт/импорт сохранения в JSON
- КаTeX для формул

## Как открыть

## Важно

- `preview=1` — **только проверка интерфейса**. Это не защита паролем и не система учительских прав.
- В общедоступном репозитории сейчас размещены ответы на тренировочные задачи первого дня в JavaScript. Для секретных будущих заданий понадобится отдельное приватное хранилище и публикация по расписанию.
- На 2–24 декабря нарисована карта и календарь, но сами игровые испытания **ещё не реализованы**.
- Ограничение по дате сейчас клиентское, для защищённого запуска потребуется настроить GitHub Actions и не публиковать содержимое будущих дней.
- 3D-ёлка пока заменена плоским макетом с наградой; настоящую вращаемую модель GLB/Three.js добавим отдельно.
- Состояния освещения теперь подгружаются из assets/locations/day01_street_lanterns_state1.webp, state2.webp, state3.webp с плавным переходом. В качестве состояния 0 используется оригинальный day01_street_lanterns.png, поскольку state0.webp пока отсутствует.
- Экспорт сохраняет только выбранный режим. Прогресс хранится в localStorage браузера.

## Объединённый маршрут дней 1–2 (версия 0.4)

- На основной карте оба дня учитываются в счётчике искр `0/24`, `1/24`, `2/24` для **текущего экзамена**.
- День 2 использует существующий ключ прогресса `chronburg:2026:day02:<oge|ege>:v1`; ранее выполненные задания не стираются. После завершения пекарни её значок на карте отмечается галочкой.
- В коллекции появляется награда второго дня — `assets/ornaments/ornament_day02_gingerbread.png`, а игрушка размещается на ёлке рядом с фонариком первого дня.
- После завершения дня 1 появляется кнопка перехода к пекарне, если локация открыта по календарю либо включён `?preview=1`.
- После завершения дня 2 показывается реплика Марты и кнопка возврата на карту, сохраняющая выбранный экзамен и режим предпросмотра.
- Важно: задания второго дня **не публикуются заранее**, они по-прежнему загружаются из локального приватного JSON учителем. Автоматическая подача ученикам после наступления 2 декабря требует отдельного этапа публикации подготовленных вопросов.

## День 3 — новогодняя почта (учительский предпросмотр)

- Игровая страница: `day03.html`, доступна с календаря Хронбурга в режиме `?preview=1`; обычный доступ по дате — начиная с 3 декабря.
- **Самостоятельная механика:** игрок перетаскивает конверт на подсвеченную ячейку. Использованы `pointerdown/pointermove/pointerup`, поддерживающие мышь и стилус/касания на планшете. Пока письмо не доставлено в нужную ячейку, математическое окно не открывается.
- Ячейки: **сортировка → марки → маршрут**, для ЕГЭ дополнительная четвёртая **отправка**. Целевая ячейка подсвечивается золотым; выполненные получают статус доставки. Неправильное перетаскивание возвращает конверт на лоток.
- Для клавиатуры и доступности предусмотрена кнопка «Поместить письмо (без перетаскивания)»; она запускает ту же процедуру доставки и только затем открывает задачу. Карточки этапов теперь служат индикаторами, не открывают задания напрямую.
- Фон почты остаётся **полноцветным** — механика не повторяет раскрашивание пекарни. Стили лежат в `css/day3-mail.css` и `css/chronburg-shared.css`.
- После правильного ответа письмо считается доставленным, появляется новое. При закрытии нерешённой задачи письмо возвращается в лоток; прогресс ОГЭ/ЕГЭ хранится раздельно.
- После третьего дня в общую коллекцию и на ёлку добавляется `assets/ornaments/ornament_day03_mailbox.png`. Счётчик карты показывает до 3/24 искр.
- **Задания и ответы будущего дня не опубликованы в репозитории.** Для проверки учитель загружает `chronburg_day03_teacher_data_PRIVATE.json` вручную; не добавляйте его в публичные файлы.
- Перед ученическим запуском нужно опубликовать задания в установленную дату и проверить полноценное прохождение на компьютере и планшете. В первоначальном основном рисунке ОГЭ №1 есть неполное обозначение, поэтому тестовый комплект использует проверенную замену.

## Общая ёлка и коллекция (дни 1–3)

- На карте (`index.html`) и в локациях `day02.html`, `day03.html` боковая панель **не показывает длинный перечень наград**: только общая ёлка, количество собранных игрушек и кнопка «Коллекция игрушек».
- Кнопка открывает модальное окно на **24 дня**. Для первых трёх дней используются реальные изображения фонарика, пряника и почтового ящика: полученные игрушки отображаются в цвете, неполученные — в оттенках серого.
- Для дней 4–24 отображаются нейтральные серые силуэты «?» без преждевременного раскрытия будущих наград. Когда появятся реальные изображения, их можно добавить в `known` в `js/chronburg-collection.js`.
- Окно открывается и закрывается кнопкой, клавишей Escape и нажатием на затемнение; сохранение, награды и независимость ОГЭ/ЕГЭ остались прежними.
- Единая реализация: `js/chronburg-collection.js` и `css/chronburg-collection.css`, подключены на всех трёх страницах.

## День 3 — игровые PNG (три состояния)

В `day03.html` подключены шесть реальных файлов из `assets/locations/`: `day03_letter_{idle,hover,done}.png` и `day03_slot_{idle,active,done}.png`. Каждая из четырёх ячеек автоматически переключает изображение между обычным, подсвеченным и доставленным состояниями. Конверт также меняет изображение при перетаскивании и принятии письма. Механика `Pointer Events`, отдельная область попадания и закрытая локальная загрузка заданий сохранены; оформление находится в `css/day3-mail.css`. Если JSON учителя ещё не загружен, можно перетаскивать письмо, но открыть математическое задание нельзя — это ограничение предпросмотра, а не ошибка кнопки.

## Очистка служебных строк рисунков

При выводе заданий дней 2 и 3, включая резервные варианты, строки, начинающиеся с `[МЕСТО ДЛЯ РИСУНКА`, удаляются из отображаемого условия. Само изображение `image` и другие поля задания не затрагиваются. Закрытые комплекты задач очищены отдельно и в публичный репозиторий не загружались.
