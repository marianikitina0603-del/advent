# Автоматический выпуск заданий Хронбурга — декабрь 2026

## Как это работает

**Хранение:** задания дней 2–3 хранятся в `data/locked/days-2026.enc.json`, а день 4 — в `data/locked/day04-2026.enc.json`; оба файла зашифрованы тем же ключом в зашифрованном виде (AES-256-GCM). Ключ в публичном репозитории **отсутствует**.

**Выпуск:** `.github/workflows/release-days.yml` по расписанию запускает `scripts/release_chronburg.py` на сервере GitHub Actions. Скрипт сверяет текущую дату по часовому поясу **Europe/Moscow (МСК)** с датой открытия и только тогда расшифровывает соответствующий день и публикует `data/day02.json`, `data/day03.json`. Он не публикует задания раньше срока, даже при ручном запуске workflow.

**Сайт:** в дни 2, 3 и 4 `js/chronburg-release-client.js` самостоятельно запрашивает опубликованный JSON. До публикации выводит статус ожидания, после — предлагает играть. Если страница оставлена открытой, повторно проверяет каждые 2 минуты. Учительский локальный импорт сохраняется в режиме `?preview=1`.

**Переустановка/миграция:** release-скрипт сам не имеет доступа к ключу. Для его запуска нужно один раз настроить секрет.

## ОБЯЗАТЕЛЬНО: один раз добавить секрет

1. Получите отдельный файл `CHRONBURG_RELEASE_KEY_PRIVATE.txt` у создателя конфигурации. Не добавляйте его в GitHub, не пересылайте ученикам и не размещайте в публичных папках.
2. Откройте **https://github.com/marianikitina0603-del/advent/settings/secrets/actions**.
3. Нажмите **New repository secret**.
4. **Name:** `CHRONBURG_RELEASE_KEY`.
5. **Secret:** вставьте единственную строку из приватного файла, без пробелов и переносов.
6. Нажмите **Add secret**.

Без секрета автоматические публикации не работают и workflow будет завершаться ошибкой; задания в репозитории по-прежнему останутся зашифрованными.

## График и пределы

| Дата (МСК) | Состояние |
|---|---|
| 1 декабря | Задания дня 1 уже встроены в публичный `data/day01.js`, доступ открывается календарём по дате |
| 2 декабря | ОГЭ (3 основных + резервы), ЕГЭ (4 основных + резервы) публикуются автоматически |
| 3 декабря | ОГЭ (3 основных + резервы), ЕГЭ (4 основных + резервы) публикуются автоматически |
| 4 декабря | ОГЭ (3 основных + резервы), ЕГЭ (4 основных + резервы) выпускаются автоматически |
| 5–24 декабря | Контент следующих дней нужно дополнительно утвердить, зашифровать и добавить в банк вместе с HTML-локациями |

**Точность времени:** GitHub Actions запускается в 00:13/00:43 и 01:13/01:43 МСК, с несколькими попытками. GitHub предупреждает о возможных задержках плановых запусков, поэтому публикация может состояться после полуночи. При опоздании следующая попытка автоматически наверстает. Сайт продолжает опрашивать сервер раз в 2 минуты.

## Проверка без досрочного выпуска

- Скрипт поддерживает `--dry-run --as-of 2026-11-30`, `2026-12-02`, `2026-12-03` для локальной проверки границ дат; аргумент `--as-of` **запрещён для настоящей публикации**.
- Вручную запущенный workflow не нарушит даты.
- После подключения секрета в GitHub **Actions → Release Chronburg daily exam tasks → Run workflow** можно проверить исполнение, оно должно сообщить, что будущие дни заперты. Пока нет даты выпуска, публичные файлы не появляются.
- Изменения, создаваемые `GITHUB_TOKEN`, не запускают обычное Pages workflow, поэтому публикация задач и развёртывание GitHub Pages выполняются **в одном** release workflow.

## Важные ограничения безопасности

- **После даты выпуска опубликованный JSON открыт всем посетителям**, в том числе технически и ответы — это подходит для календаря, но не для защищённого экзамена.
- Задания первого дня уже находятся в истории публичного репозитория; календарная блокировка не удаляет их из GitHub.
- Будущие дни до публикации не должны попадать в обычные публичные JSON/JS, README, логи или исходный код HTML. Шифрованный банк без секрета не раскрывает содержимое.
- Не загружайте ключ как GitHub Actions artifact, не вставляйте его в коммиты и не сохраняйте в общедоступных текстах.
- Если ключ утрачен, зашифрованный банк нельзя восстановить. Если ключ раскрыт, необходимо заново зашифровать банк новым ключом и заменить секрет.

## Файлы

- `.github/workflows/release-days.yml` — расписание, commit и Pages deploy.
- `scripts/release_chronburg.py` — проверки календаря, ключей, изображений и выпуск.
- `data/locked/days-2026.enc.json` — единственная публичная зашифрованная копия подготовленных данных дней 2, 3 и 4.
- `js/chronburg-release-client.js` — автоматическая загрузка опубликованного содержимого.
- `day02.html`, `day03.html` — игровые экраны; импорт JSON остаётся только в предпросмотре.

Последняя локальная проверка: для 30 ноября не выпускается ничего; для 2 декабря — только день 2; для 3 декабря — дни 2, 3 и 4, повторный запуск не меняет уже опубликованное.

## Четвёртый день — сборка механизма

Игровая сцена `day04.html` использует `js/day4-workshop.js` и `css/day4-workshop.css`. После верного ответа очередная деталь закрепляется в механизме. Для ОГЭ три задания; четвёртая, золотая деталь добавляется автоматически в финале. Для ЕГЭ четыре задания. Коллекционная награда — `assets/ornaments/ornament_day04_clockwork_gear.png`.

Содержание четвёртого дня зашифровано отдельно в `data/locked/day04-2026.enc.json` тем же ключом `CHRONBURG_RELEASE_KEY`. **Новый секрет добавлять не требуется.** Дата открытия — 4 декабря 2026 г. по времени Europe/Moscow. Проверочная workflow теперь включает граничную дату 4 декабря.

Пять фоновых состояний и восемь изображений игровых деталей (`day04_toy_workshop_*.png`, `day04_part_*.png`) уже проверены в `assets/locations/` и используются страницей. Иллюстрированная SVG-сцена остаётся резервом на случай ошибки загрузки PNG.
