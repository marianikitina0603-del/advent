## Исправления этого аудита

1. **День 2:** до поступления заданий основной вызов и недоступные активные маркеры не запускают бессмысленную ошибку. Для преподавателя в режиме `?preview=1` остаётся локальная загрузка.
2. **День 3:** основной вызов недоступен до поступления банка; при попытке перетаскивания без задач ученику объясняется ожидание, а не предлагается загрузить преподавательский JSON.
3. **День 5:** до выбора пути больше не показывается пунктир правильной ветки; золотая линия остаётся только на пройденных участках. Поле ввода ответа и цифровая клавиатура получили явно тёмный текст на светлом фоне.
4. **Главная карта:** убран повтор предложения о блокировке будущих дней.
5. **GitHub Actions:** безопасный тест календаря теперь запускается не только при изменении своего workflow, но также при изменении скрипта выпуска, зашифрованных банков и математических рисунков.

## Настройки публикации

- Московское время (`Europe/Moscow`).
- Первый день уже имеет публичный код задач; для дней 2–5 пока лежат только зашифрованные банки.
- В `js/chronburg-release-client.js` прописаны 2, 3, 4, 5 декабря 2026 года; новые файлы `data/dayXX.json` загружаются клиентом без ручного JSON.
- Workflow `release-days.yml` имеет расписание, ручной запуск и публикацию Pages после создания новых JSON.
- В Github Actions имеется безопасный тест `release-safety-test.yml` с датами до 5 декабря.
- **Не подтверждено здесь:** фактическое выполнение последних версий Actions и первый настоящий выпуск в 00:13 МСК. Успех самопроверки на более раннем скриншоте не заменяет проверку после новых коммитов.

## Что требует визуального браузерного теста

**Не выполнено в этой среде:** настоящая загрузка GitHub Pages в Chrome на десктопе и планшете, screenshots всех 5 игровых состояний и проверка текущего deployed Pages. Публичный URL недоступен через используемые web/container-инструменты, поэтому не утверждаем, что полноценный pixel-by-pixel / device-test проведён.

Рекомендуемая ручная проверка в браузере:
- 1366×768: главная карта, страницы дней 2–5, модальное математическое окно.
- Планшет 768×1024: все активные объекты доступны касанием, нет перекрытий после поворота экрана.
- Телефон 390×844: календарь 24 дней, легенда, кнопки, модальное окно, коллекция 24 игрушек.
- День 2: 3/4 промежуточных оттенка и переход к полной цветной пекарне.
- День 3: 3 картинки письма и 3 картинки ячейки, Pointer Events и доступная кнопка «без перетаскивания».
- День 4: 5 состояний помещения, 4 детали обычная/подсвеченная, ОГЭ 3 шага и ЕГЭ 4 шага.
- День 5: **каждая** из четырёх правильных и четырёх неправильных траекторий на карте, концы траекторий, отсутствие телепортации через крыши, корректное выравнивание кнопок при адаптации ширины.
- Локальная учительская проверка до даты: `?preview=1` + проверенный закрытый JSON для дней 2–5; открытый GitHub не должен содержать его в исходном коде.

## Действия перед первым декабря

1. Открыть страницы в Chrome и проверить на двух ширинах экрана.
2. Запустить `Chronburg release safety self-test` в GitHub Actions и убедиться в зелёной отметке после этого аудита.
3. Убедиться, что Pages настроен на автоматическое развёртывание из GitHub Actions, а `CHRONBURG_RELEASE_KEY` остаётся только в секретах.
4. После первого фактического планового выпуска отдельно проверить страницу дня 2, статус release и открытие всех заданий без локального файла.
